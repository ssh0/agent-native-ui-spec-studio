# 業務フローの実機確認

サンプル仕様を使った一時的なローカルページで、MermaidのSVG描画、左から右への手順順序、横スクロール、倍率の変更・リセット、390px幅での表示を確認した。認証済みの `/spec` 画面での全ワークフローは未確認。
以下は稼働環境での追加確認手順。既存仕様は自動変換しないため、確認には新しい `specs/example.yaml` を使う。
既存の共有仕様を置き換える場合は、元のYAMLを退避してから行う。

1. `/spec` の「YAMLを直接編集」でサンプルを読み込み、保存・再読込後に検証エラーがないことを確認する。
2. 「業務フロー」で「作業の受付と登録」を選ぶ。依頼者・チームメンバー・通知サービスの担当区間が左から右へ並び、1〜6の手順、区間間の矢印、登録手順のUC名が見えることを確認する。
3. 「アクター・外部システムを編集」を開く。両方の種類で追加・名称／説明編集・未参照項目の削除ができることを確認する。参照中の削除は無効であることを確認する。
4. `member` のIDを変更し、YAML内の対応する `performer.id` が追従することを確認する。名称変更が図へ反映され、保存・再読込後も維持されることを確認する。
5. 「この段階を編集」で手順の `performer` を別のアクター／外部システムへ変更する。手順とレーンが更新されること、`useCase` のない手作業・外部処理も表示されることを確認する。
6. 存在しない `performer.id`、不正な `kind`、重複ID、存在しない `useCase` を順に入力し、検証エラーと対象パスが表示され、図・レビューが抑止されることを確認する。修正すると復帰することを確認する。
7. `steps: []` と `flows: []` の空状態、別フローへの選択変更、狭い画面でのスクロール、拡大・縮小・100%へのリセット、倍率の上下限、キーボードによる入力・開閉を確認する。
8. 既存3種も確認する。「ユースケース」で分岐・例外と再開矢印、「画面・状態」で画面遷移図とタスク登録の画面状態図が描画されることを確認する。
9. エージェントから `spec-render-flow` に `kind: flows`、任意 `selectedId: task-intake` を渡し、`format: mermaid` とUIと同じ生成ソースが返ることを確認する。`screens` / `useCases` / `states` の既存指定も確認する。

Mermaidの試作は一時編集であり、保存される業務定義は構造化YAMLのみ。
業務フロー図の表示仕様は [spec-format.md](./spec-format.md) を参照。
