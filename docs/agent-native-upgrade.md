# Agent-Native 0.198.8 更新と機能の適用検討

## 更新範囲

npmレジストリの `latest` を照会し、Core 0.182.1、AgentKit 0.2.4、Toolkit 0.20.4 をいずれも安定版 0.198.8 に更新した。ロックファイルで解決版を固定する。対象はAgent-Nativeと互換性維持に必要な依存関係であり、アプリの仕様モデルや提案・承認ルールは変更しない。

同梱の `node_modules/@agent-native/core/docs/content/upgrading-core-ui.mdx` を移行の根拠とする。

- ReactのAgentKit画面、設定、ナビゲーションなどの共有UIとCSSを、公開されたToolkitの参照先に移行。Coreは実行エンジン・データ・通信を引き続き担当する。既存のprovider-safe-engineも保持する。
- 廃止された `@agent-native/toolkit/marketing` に代わり、公開トップページをアプリ側の静的JSXで維持。文言、SEOメタデータ、プロジェクト・サインインへのリンクは保持する。旧コンポーネントの装飾背景は移植しない。
- 認証設定から廃止されたスクリーンショット用プロパティを削除。公開パス・認証方式は変更しない。
- 旧Coreが提供していたOffice解析・画像処理のoptional dependenciesをアプリの直接依存にする。`officeparser`、`mammoth`、`xlsx`、`jszip`、`sharp` に加え、拡張HTMLの整形用 `prettier`、Anthropicのトークン計数用 `@anthropic-ai/tokenizer` を明示する。新しいアップロード経路や保存先は作らない。
- テンプレートのソースコーパスが別パッケージになったため、Coreと同版の `@agent-native/core-corpus` を開発依存に追加。ソース検索を本番でも必要とする配備では、開発依存を含めるか実行時依存へ移すことを配備側で確認する。
- `agent-native.scaffold.templateRef` と `coreVersion` は生成時の来歴なので0.182.1のまま保持。パッケージ更新をテンプレート同期として扱わない。
- pnpmが追加したrelease-age例外は今回の正確なパッケージ版だけに限定する。フレームワークへのpatchやoverrideは追加しない。

## 機能の適用検討

旧版と更新版の同梱ドキュメントを比較した。以下は更新で新たに確認できた機能・移行点と、既存機能を含む適用候補であり、すべてが今回初めて実装された機能という意味ではない。

| 機能・変更                    | このアプリでの扱い                                                                                   | 根拠・追加条件                                                                                                                                       |
| ----------------------------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Core/Toolkitの責務分離        | 今回適用。既存のチャット・設定・履歴を新しい公開UI APIで維持する                                     | `upgrading-core-ui.mdx`                                                                                                                              |
| テンプレートソースの別配布    | 今回適用。エージェントが版に合う実装例を調べるために利用する                                         | `upgrading-core-ui.mdx`、`source-search` の実装                                                                                                      |
| Account設定のプライバシー要求 | 共有Account設定を継続利用するため、フレームワーク側の要求受付UIを利用可能。運用手順の整備は別途必要  | 新たに同梱された `privacy-and-data-rights.mdx`。要求記録だけで、仕様・添付・バックアップを自動削除する機能ではない。運用者の本人確認・履行手順が必要 |
| Office・画像の参考資料解析    | 既存機能を維持。直接依存へ移し、Core API経由でXLSX・DOCX・画像の簡易回帰テストを追加                 | `upgrading-core-ui.mdx`、`file-uploads.mdx`。実際のアップロードには設定済みのblobストレージが必要。PDF・PPTXや外部ストレージ経由の動作は別途確認     |
| Context X-Rayの可視化         | 適用候補。長い仕様検討で参照資料や会話のコンテキストを確認する用途に合うが、今回は専用UIを追加しない | `toolkit-context-knowledge.mdx`。Toolkitの表示部品とCoreのpin/evict等のアクションを組み合わせる必要がある。独自の権限チェックを省略しない            |
| Public Agent Web / WebMCP     | 今回は新たに有効化しない。仕様と会話は認証・所有権で保護し続ける                                     | `agent-web-surfaces.mdx`、`webmcp.mdx`。公開する情報・アクションの個別判断が必要                                                                     |
| テンプレート同期              | 今回は実行しない。仕様スタジオ固有の変更を保ち、更新とテンプレートのマージを分離する                 | `syncing-template-changes.mdx`。利用する場合は差分・ベースライン・競合を先に確認する                                                                 |

## 検証と配備境界

再検証には `pnpm typecheck`、`pnpm test --maxWorkers=1`、`pnpm agent-native:doctor` を使う。追加テストは公開トップページのSSRと、Coreの公開APIからのOffice・画像処理、依存パッケージの版整合性を確認する。添付データはテスト内で生成し、SQLや外部サービスへ保存しない。

`pnpm peers check` には既存のTypeScript 7とReact Router、および更新版i18nextの宣言範囲（TypeScript 5/6）の不一致が残る。型チェック結果とは区別し、フレームワーク更新とは別のコンパイラ移行判断として扱う。

ブラウザーの操作確認、本番ビルド、外部ストレージ経由の添付、実プロバイダーとの会話、プライバシー要求の履行はこのローカル検証には含めない。本番の認証・DB・ストレージ・任意peerの設定は `DEVELOPING.md` の配備境界に従って確認する。

`pnpm action source-search --query ui-spec-project` のCLI実行は30秒でタイムアウトしたため、検索アクションの完走は未確認。起動した検証プロセスは停止した。コーパスの導入・版整合性のテストと、このCLI動作確認は区別する。
